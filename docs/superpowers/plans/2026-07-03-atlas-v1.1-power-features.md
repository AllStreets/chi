# CHI ATLAS v1.1 — Power Features Plan (2026-07-03)

Approved sequence (user: "implement all of that in order"):

1. **Foundation** — React.lazy route code-splitting w/ HUD Suspense fallback;
   shared `useAtlasMap()` hook (map init, resize, cleanup) adopted by the 4 map pages.
2. **Lighting + deep search** — dawn/day/dusk/night pills on Home (Mapbox Standard
   `lightPreset`, solar-time default); backend `/api/search` over places/events/
   neighborhoods/stations; ⌘K palette gains result sections + map fly-to via
   `?focus=lon,lat,name` param on map pages.
3. **Transit time-machine** — backend snapshot recorder (SQLite `cta_snapshots`,
   60s cadence, 24h retention) + `/api/cta/history`; Transit scrubber bar
   (play/pause, 1×/30×/60×, big mono clock, LIVE return).
4. **ATLAS AI + Get me there** — `/api/ai/concierge` with OpenAI tool-calling over
   existing endpoints (places, events, weather, sports, arrivals, alerts); palette
   "Ask ATLAS" mode. Venue popups/cards get nearest-L-station + next arrivals
   (new `/api/cta/stations` from City of Chicago L-stops dataset, cached).
5. **Push preferences** — Settings toggles (game start, severe weather, great lake
   day, line delays) stored per-subscription; backend condition checker every 5 min
   sends web-push via existing VAPID setup.
6. **Extras** — Atlas Mode (chrome-hiding ambient orbit), My Chicago itinerary
   mini-map, PWA manifest/icons. Final verify + push.

Constraints: zero feature regressions; all 36 frontend tests + backend suite stay
green; each phase commits separately; keep CHI ATLAS HUD design language.
